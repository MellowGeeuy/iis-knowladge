## สิ่งที่เพิ่ม

### ส่วนที่ 01 — ส่ององค์ประกอบทั้งสามบนเครื่องจริง
เดิมอธิบาย HTTP.sys / W3SVC / WAS / w3wp ได้ดี แต่ผู้อ่านเอาไปตรวจกับเครื่องตัวเองไม่ได้เลย ไม่มีคำสั่งสักบรรทัด
- ตารางจับคู่ "อยากรู้อะไร → ใช้คำสั่งไหน → จะเห็นอะไร" 6 แถว
- บล็อกคำสั่ง PowerShell ไล่จากชั้นเคอร์เนล → service → process
- กล่องเตือนว่า W3SVC กับ WAS อยู่ใน `svchost.exe` ตัวเดียวกัน จึงได้ PID เดียวกัน และ restart ตัวหนึ่งกระทบอีกตัว
- วิธีแยกว่า response มาจาก HTTP.sys หรือ IIS ด้วย header `Server`

### ส่วนที่ 02 — เติมเกณฑ์ตัดสินใจที่เอกสารสัญญาไว้
- ตารางเทียบสี่หน่วย 5 คอลัมน์ (มี binding · กำหนด pool เองได้ · โผล่ใน URL · ชี้โฟลเดอร์จริง)
- เกณฑ์ตัดสินใจเป็นคำถามสามข้อเรียงลำดับ ตอบ "ไม่" ครบสามข้อ = ไม่ต้องสร้างหน่วยใหม่
- โครง `<sites>` จริงใน `applicationHost.config` พร้อมชี้ว่า `path="/"` คือ root object
- คำสั่งเปิดดูหน่วยทั้งสี่ และกล่องเตือนสองกรณีที่ "แก้ pool แล้วไม่มีผล"

### ส่วนที่ 09 — ทำให้เป็นบทวิเคราะห์ปัญหาที่ใช้ได้จริง
เดิมมีตารางอาการ 8 แถวแต่ไม่บอกว่า log อยู่ที่ไหนและอ่าน field ไหน
- ตารางตำแหน่ง log ทั้ง 4 ชั้น (httperr · IIS log · FRT · log ของ upstream)
- ตารางนิยาม W3C field 5 ตัวที่ต้องอ่าน พร้อมบอกว่าแต่ละตัวตอบคำถามอะไร
- บล็อก PowerShell กรอง request ที่ไม่ใช่ 200 และหา request ที่ช้ากว่า 3 วินาที
- ตาราง substatus 10 รหัสที่เกิดได้จริงกับสถาปัตยกรรมนี้ พร้อมสาเหตุในบริบทนี้
- กล่องเตือนว่ารหัสย่อยของ 401 ไม่ถูกเขียนลง IIS log
