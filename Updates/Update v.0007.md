**วันที่:** 2026-09-15 · **ไฟล์ที่แก้:** `index.html` · `iis-knowladge.md`

## ที่มา
พยายามจัดผังให้เป็นระเบียบมาหลายรอบแล้วติดกำแพงเดิมทุกครั้ง จัดเป็นคอลัมน์ได้เส้นพาดผ่านกล่อง 112 เส้น
relax ใหม่ทั้งกราฟได้ 233 เส้น สรุปว่า **เส้นตรง + กล่องกว้างตามชื่อ = ผังต้องกระจายแบบ organic เท่านั้น**

ไปดู graph view ของ Obsidian แล้วพบว่าเขาไม่ใช้กล่องตั้งแต่แรก เอกสารระบุว่า node เป็นวงกลมที่
*"The more nodes that reference a given node, the bigger it gets"* พอ node กินพื้นที่แค่วงเล็ก ๆ
ปัญหาที่ชนมาทั้งวันก็เกือบหายไปเอง

## สิ่งที่แก้

### node เป็นวงกลม ขนาดตามจำนวนความสัมพันธ์
- รัศมี = `5 + degree × 1.75` → 6.8px (1 เส้น) ถึง 19px (`w3wp.exe` 8 เส้น)
- ชื่อย้ายออกมาอยู่นอกวง หาที่ว่างรอบวงให้ทั้ง 60 ตัว
- force layout ใช้แรงสี่ตัวชุดเดียวกับที่ Obsidian มีให้ปรับ — center force · repel force · link force · link distance

### animation ตอนชี้
- ชี้ที่ node → วงรัศมีเปล่งออกมา `scale(.55) → scale(2.8)` ด้วย `cubic-bezier(.32,1.4,.5,1)` 340ms
- เพื่อนบ้านเปล่งวงเล็กกว่า `scale(2.2)` ส่วนที่เหลือจางลงเหลือ 14%
- เส้นที่เกี่ยวเปลี่ยนเป็นสี accent พร้อม `flowDash` วิ่ง และชื่อความสัมพันธ์ทุกเส้นโผล่พร้อมกัน
- ชื่อ node ของตัวที่ถูกชี้และเพื่อนบ้าน **อ่านได้เสมอไม่ว่าซูมระดับไหน**
- คลิกถึงจะเปิด modal เหมือนเดิม

### กล้องซูม
- ลากเลื่อน หมุนล้อซูม ปุ่ม + − และพอดีจอ
- ชื่อ node จางหายเมื่อซูมต่ำกว่า 42% ตามแนวคิด Text fade threshold ของ Obsidian
- **บั๊กที่เจอ** — `viewBox` ย่อเนื้อหาให้พอดีกรอบอยู่แล้ว พอใส่กล้องซูมอีกชั้นเลยถูกย่อซ้ำ
  กราฟออกมาเล็กนิดเดียว แก้ด้วยการตัด `viewBox` ทิ้งแล้วให้กล้องคุมการย่อขยายคนเดียว

## บั๊กที่ตามมา — คลิก node แล้ว modal ไม่เปิด

ตอนแรกใส่ `gNodes.appendChild(n)` ใน `mouseenter` เพื่อยก node ที่ถูกชี้ขึ้นบนสุด ไม่ให้วงรัศมีถูกวงอื่นทับ
ผลคือ **คลิกแล้ว modal ไม่เปิดเลย** ทั้งที่ทดสอบด้วย synthetic event ผ่าน

สาเหตุจาก log ของ event จริง

```
pointerdown → closestNode=site     ← เริ่มที่ node ถูกต้อง
mousedown   → closestNode=none     ← เป้าหมายกลายเป็น group
pointerup   → closestNode=site
mouseup     → closestNode=none
(ไม่มี click เลย)
```

การย้าย DOM ระหว่าง `pointerdown` กับ `mousedown` ทำให้ hit-test ตกไปที่ group แทน node
เมื่อ mousedown กับ mouseup อยู่คนละ element เบราว์เซอร์จึงยิง `click` ที่บรรพบุรุษร่วมแทน
handler ของ node เลยไม่ถูกเรียก

แก้ด้วยการเอา `appendChild` ออก วงรัศมีถูกวงอื่นทับบ้างไม่เป็นไร เพราะตัวที่ไม่เกี่ยวจางเหลือ 14% อยู่แล้ว

**บทเรียน** — synthetic event ที่ dispatch แยกทีละตัวไม่เจอบั๊กประเภทนี้ ต้องคลิกด้วยเมาส์จริง
